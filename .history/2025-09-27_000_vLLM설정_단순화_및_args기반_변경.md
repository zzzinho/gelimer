# 작업 히스토리: vLLM 설정 단순화 및 args 기반 변경

**날짜**: 2025-09-27 17:30:12
**작업자**: Claude

## 작업 개요
- vLLM 설정을 복잡한 중첩 구조체에서 단순한 args 배열 방식으로 변경
- CRD 구조 단순화 및 컨트롤러 로직 개선
- vLLM 버전 의존성 문제 해결

## 수정된 파일
- `api/v1alpha1/llm_types.go` - VLLMConfig 구조체 단순화, 복잡한 중첩 구조체들 제거
- `internal/controller/v1alpha1/llm/vllm.go` - 복잡한 config 빌드 로직 제거, 단순한 args 처리로 변경
- `internal/controller/v1alpha1/llm/reconciler.go` - buildVLLMArgs 함수 단순화, 불필요한 상수 제거
- `CLAUDE.md` - 한국어 사용 규칙 및 히스토리 생성 강제 규칙 추가

## 작업 상세 내용

### 1. LLM CRD 구조 단순화
**변경 전:**
```go
type VLLMConfig struct {
    Model *ModelConfig
    Load *LoadConfig
    Decoding *DecodingConfig
    Parallel *ParallelConfig
    Cache *CacheConfig
    LoRA *LoRAConfig
    Scheduler *SchedulerConfig
    ExtraArgs map[string]string
}
```

**변경 후:**
```go
type VLLMConfig struct {
    Command []string `json:"command,omitempty"`
    Args []string `json:"args,omitempty"`
}
```

### 2. 컨트롤러 로직 단순화
- 복잡한 config 빌드 로직 300+ 라인 제거
- 기본 인수(`--model`, `--host`, `--port`)만 설정
- 추가 설정은 사용자가 args 배열로 직접 전달

### 3. 사용 방법 개선
**이전 방식:**
```yaml
runtimeConfig:
  vLLM:
    parallel:
      tensorParallelSize: 2
    model:
      maxModelLen: 4096
```

**새로운 방식:**
```yaml
runtimeConfig:
  vLLM:
    args:
      - "--tensor-parallel-size"
      - "2"
      - "--max-model-len"
      - "4096"
```

- 기존 복잡한 구조체 기반 설정은 더 이상 지원되지 않음
- 모든 vLLM 설정은 이제 args 배열을 통해 직접 전달 필요

- 향후 다른 LLM 런타임도 동일한 패턴으로 단순화 예정
